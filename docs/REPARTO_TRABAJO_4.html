Objetivo y reglas del equipo

Entregar un sistema funcional con 12 entidades @Entity, relaciones JPA bidireccionales donde corresponda, CRUD completo, 4 consultas HQL, interfaz JavaFX, validaciones y trabajo verificable de los cuatro colaboradores en GitHub.

El repositorio RomanVark/Examen_final es la referencia original de estructura. Este paquete no realiza cambios en ese repositorio. Antes de integrar, acordad si trabajaréis sobre el repositorio existente o uno nuevo; con el existente, su rama principal actual es master.

Importante: no basta con que una persona suba el ZIP completo y cuatro personas hagan commits vacíos. Cada integrante debe realizar mejoras reales en su rama, demostrar pruebas y solicitar una revisión externa. Los mensajes siguientes son ejemplos, nunca sustitutos de trabajo realizado.

Distribución equitativa: 3 entidades por integrante

Los responsables están tomados del README del repositorio de referencia. Si la composición del equipo cambia, pueden editar este archivo HTML. Cada persona entrega entidad + CRUD probado + validaciones + mejora complementaria + PR revisado.

Secuencia paso a paso: desde cero hasta la entrega

  1. Acuerdo inicial (todos, antes de editar) Revisar `README.md`, `docs/ARQUITECTURA.md` y `sql/01_esquema.sql`. Acordar paquetes, nombre de base, responsables, reglas de validación y calendario. Crear cuatro cuentas/collaborators con acceso al repositorio.
  2. Clonar y crear ramas personales Clonar el repositorio, comprobar la rama predeterminada actual (en la referencia es master), partir de una versión base compartida y crear ramas `feat/academico-roman`, `feat/empresas-cristopher`, `feat/asignaciones-alfredo` y `feat/seguimiento-celeste`.
  3. Preparar el entorno (cada integrante) Instalar Temurin 21.0.12, Maven, PostgreSQL, IntelliJ y opcionalmente Scene Builder. Ejecutar SQL 00 en `postgres`, SQL 01 y 02 en `practicas_profesionales`; probar con SQL 03. Definir `DB_PASSWORD` localmente, nunca en Git.
  4. Reemplazar la plantilla Hello Tomar como referencia la estructura Maven original. La base compartida integrada debe usar el paquete `ni.edu.uam.practicasprofesionales`, la clase `PracticasProfesionalesApplication`, `Launcher`, `module-info.java` y cuatro FXML. Eliminar `HelloApplication`, `HelloController` y `hello-view.fxml` en la copia de trabajo, nunca modificar el repo remoto sin un PR.
  5. Implementar por dominios Cada integrante modifica y comprueba las tres entidades asignadas, sus columnas SQL, validaciones, presentación en `EntityCatalog` y las pruebas del módulo. Coordinar cambios en archivos compartidos: `pom.xml`, `EntityCatalog`, `CrudController`, `app.css` y SQL.
  6. Validar operaciones y reportes Ejecutar al menos un alta, lectura, búsqueda, actualización, eliminación válida, error de integridad referencial y validación negativa por módulo. Verificar las cuatro HQL y exportar un CSV desde JavaFX.
  7. Enviar PR individuales y revisar Cada integrante registra varios commits pequeños, hace push de su rama y abre Pull Request hacia master con cambios, capturas y pruebas. La revisión se realiza en ciclo: Cristopher → PR de Roman; Alfredo → Cristopher; Celeste → Alfredo; Roman → Celeste.
  8. Integración final (todos) Solo fusionar PR aprobados. Tras cada merge: actualizar `master`, `mvn clean test`, `mvn clean compile`, `mvn javafx:run`, repetir pruebas de BD, revisar FXML con Scene Builder y resolver conflictos sin borrar trabajo de otro equipo.
  9. Entrega y demostración Compartir enlace GitHub con historia auténtica, ejecutable en IntelliJ, scripts SQL, README seguro y capturas de Git/CRUD/consultas. Todos explican sus módulos y su PR.

Comandos Git de trabajo diario

Ejecutar una vez por cada integrante, sustituyendo el nombre de rama por su asignación. Para un repositorio recién preparado, integrad una sola versión base compartida mediante un PR inicial y luego desarrollad mejoras individuales reales.

git clone https://github.com/RomanVark/Examen_final.git
cd Examen_final
git switch master
git pull origin master
# Ejemplo: Roman (otros sustituyen rama)
git switch -c feat/academico-roman

# Después de modificar realmente los archivos de su módulo:
git status
git add src/main/java/ni/edu/uam/practicasprofesionales/model src/test/java/ni/edu/uam/practicasprofesionales/repository
git commit -m "feat(academico): mejorar validación de estudiantes"
git push -u origin feat/academico-roman

# Abrir en GitHub: Pull requests -> New pull request
# base: master  <- compare: feat/academico-roman
# Solicitar revisión al compañero y corregir observaciones.

# Al fusionar un PR aprobado:
git switch master
git pull origin master
mvn clean test
mvn clean compile
mvn javafx:run

El comando git add se proporciona en una sola línea para funcionar en PowerShell, CMD y Bash. También puedes hacer `git add -A` tras comprobar cuidadosamente `git status` y `.gitignore`.

Comandos para PostgreSQL + JavaFX

# 1. Verificar el SDK exacto instalado
java -version
mvn -version

# 2. Ejecutar scripts por orden desde psql (te preguntará contraseña)
psql -h localhost -U postgres -W -d postgres -f sql/00_crear_base.sql
psql -h localhost -U postgres -W -d practicas_profesionales -f sql/01_esquema.sql
psql -h localhost -U postgres -W -d practicas_profesionales -f sql/02_datos_ejemplo.sql

# 3. PowerShell: variables SOLO para esta sesión
$env:DB_URL="jdbc:postgresql://localhost:5432/practicas_profesionales"
$env:DB_USER="postgres"
$env:DB_PASSWORD="1234"

# 4. Ejecutar y probar
mvn clean test
mvn javafx:run

Si tu base ya existe, omite 00_crear_base.sql. Cambia `1234` por la contraseña local si usas otra. El archivo `persistence.xml` no contiene credenciales y Hibernate valida, pero no crea/modifica, el esquema SQL.
